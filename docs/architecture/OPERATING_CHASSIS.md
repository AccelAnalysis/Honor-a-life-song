# Honor a Life Song Operating Chassis

## Architectural rule

Honor a Life Song is one platform with a shared meaning-to-song engine. Individual/family services, Project Ageless and future program templates use the same people, organization, story, creative-work, consent, payment, communication, media and delivery boundaries. Project Ageless is not a separate application.

## Four shells

1. **Public / Acquisition** — marketing, service education, Project Ageless, stories, partnerships, pricing, request entry and public legal/support destinations.
2. **Identity / Access** — login, registration, verification, password recovery, invitation acceptance, MFA and access/consent error states.
3. **Authenticated Workspace** — one persistent responsive composition with role-aware Customer, Facility, Creator and Admin navigation.
4. **Secure Delivery** — entitlement- and consent-aware final song/keepsake access.

## Chassis ownership

The chassis owns:

- route hierarchy and navigation registry;
- workspace context boundaries;
- responsive application composition;
- canonical domain contracts;
- workflow state contracts;
- consent contracts;
- progressive availability;
- shared loading, empty, unavailable and error patterns;
- synthetic reference-data boundary;
- CI and architecture documentation.

Business modules must plug into these contracts rather than redesign shell composition.

## Reference mode

The current chassis uses clearly labeled synthetic context for visual acceptance. It does not claim production authentication, authorization, participant records, payment, storage, messaging, scheduling, analytics or delivery behavior.

## Non-negotiable safety boundary

A user being authorized to view or act on a record does not imply a participant has consented to a particular use. Downstream actions involving recordings, family sharing, performance, photography/video, public marketing, sponsor acknowledgment, testimonials or extended retention must evaluate both authorization and consent.
